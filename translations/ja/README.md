# gt-demo

実際には、多くのデータは 非境界（unbounded）です。なぜなら、データは時間の経過とともに次々と到着するからです：ユーザーは昨日と今日データ生成し、明日もさらに多くのデータを生成し続けるでしょう。あなたの企業が事業を営んでいる限り、このプロセスが終わることはないため、どんな意味のある観点から見ても、データセットが「完全」になることは決してありません1。そのため、バッチ処理プログラムは人為的に固定時間でデータを分割せざるを得ません。たとえば、一日の終わりにその日のデータを処理したり、一時間の終わりにその時間のデータを処理したりします。[guide.md](../../docs/guide.md)

毎日のバッチ処理の問題は、入力の変化が出力に反映されるまでに一日かかることであり、多くの気の短いユーザーにとってはあまりにも遅すぎます。遅延を短縮するために、処理をより頻繁に実行できます——たとえば毎秒の終わりにその秒のデータを処理する——あるいは、固定の時間スライスを完全に捨てて、連続処理に切り替え、各イベントが発生した時点で即座に処理することもできます。これが ストリーム処理（stream processing） の基本的な考え方です。

一般に、「ストリーム」とは、時間の経過とともに徐々に利用可能になるデータのことを指します。この概念は多くの場所に現れます：Unix の stdin と stdout、プログラミング言語における遅延リスト2、ファイルシステム API（たとえば Java の FileInputStream）、TCP 接続、インターネット経由で伝送される音声と動画、などです。
